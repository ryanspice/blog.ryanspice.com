>
> **Clean read.** Keyword Astro is more credible when it is used on itself. The product should show its own metadata drafts, screenshot proof, source labels, export paths, and release gates.
>
> **Operator read.** The product should not claim Astro-grade popularity, difficulty, automated rank history, or competitor intelligence until those sources are official, licensed, imported, or otherwise defensible.
>
> | Area | Current decision |
> | --- | --- |
> | RC promise | Windows-first local ASO workflow |
> | Sales promise | Cross-store metadata drafting and evidence capture |
> | Proof | Screenshots, projects, exports, snapshots, source confidence |
> | Deferred | Paid final release, signed hosted package, hard ranking claims |

Keyword Astro started with a simple problem: app-store keyword work gets messy fast. Apple, Google Play, Microsoft Store, screenshots, metadata drafts, translations, and release evidence all become separate fragments unless the workflow gives them a place to live.

The self-case study is the product discipline: use Keyword Astro to sharpen Keyword Astro.

## What using the tool on itself changed

The sales site and product language moved toward a narrower, more defensible promise:

- Windows-first desktop workflow.
- Local-first project storage.
- Apple App Store, Google Play, and Microsoft Store metadata lanes.
- Screenshot and release evidence as part of the product story.
- Imported/manual snapshots for rank/history until a compliant source exists.
- RC/final split so signing, hosted installers, and paid fulfillment do not block the proof release.

That is a cleaner promise than “clone Astro.” Astro is a useful benchmark for simplicity and confidence. Keyword Astro’s lane is different: practical Windows-first ASO workflow with local evidence and transparent source states.

## The important claim boundary

The product should be explicit about what it does and does not prove.

| Claim | Safe today? | Why |
| --- | --- | --- |
| Draft Apple keyword fields | Yes | Local generation and user copy/export are product behavior. |
| Save metadata drafts to projects | Yes | Local project persistence is visible. |
| Import rank snapshots | Yes | User-provided CSV/JSON imports are controlled evidence. |
| Automated organic rank tracking | No | Needs an official/licensed/source-safe path before public claim. |
| Popularity/difficulty metrics | No | Must not imply Apple Search Ads-style metrics without a valid source. |
| Revenue or ranking lift | No | Needs published before/after evidence. |

That boundary makes the product more saleable, not less. Buyers can tell the difference between a sharp tool and a fake dashboard.

## Evidence that exists now

The useful proof is visual and operational:

- Store Research Console screenshot with platform lanes.
- Explorer screenshot with visible batch progress.
- Projects and exports workflow.
- RC release docs and artifact manifest language.
- Sales site copy that separates RC readiness from paid final release.
- Canopy case-study links that place the tool inside a broader productization system.

This is enough for a waitlist, RC download-readiness page, and consulting CTA. It is not enough for a paid final product claim until the artifact, support, fulfillment, and legal pages are all aligned.

## What Keyword Astro proves as a method

Keyword Astro is not only a product. It is also a repeatable working method:

1. pick a platform lane;
2. draft metadata;
3. attach source confidence;
4. capture screenshots;
5. save project evidence;
6. export the working set;
7. map the missing saleability proof.

That method is what connected PixelBoats, Keyword Astro, and QBO Mail Dashboard into a single case-study system.

## The saleability gap

The gap is concrete:

| Area | Ready | Missing |
| --- | --- | --- |
| Product story | Windows-first local ASO console | External user proof |
| Visual evidence | App screenshots and marketing screenshots | Fresh cross-device browser QA set |
| Download | RC language and artifact manifest model | Signed/hosted final package |
| Payments | Configurable CTA pattern | Fulfillment, refund, support, delivery proof |
| Differentiation | Local-first cross-store workflow | Measured store outcome from a real app |

The next high-value proof item is a public article showing how Keyword Astro improved a real product surface, with screenshots before and after. PixelBoats is the best candidate because its product lane changed visibly.

## Practical bottom line

The strongest saleable version of Keyword Astro is not “another ASO metric dashboard.” It is a practical ASO workbench for builders who need to make store pages, screenshots, translations, imports, and project evidence less scattered.

That is narrower than Astro’s public promise. It is also more defensible for a Windows-first local product.
